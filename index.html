SpermaCore Plugin API

Справочник по C ABI для написания плагинов

Обзор

SpermaCore — модульное ядро на Go + cgo. Вся функциональность агента реализуется через плагины — динамические библиотеки (.dll, .so, .dylib), которые загружаются во время выполнения.

Плагин ничего не знает о ядре кроме контракта, описанного в одном заголовочном файле include/plugin_api.h. Контракт стабилен, версионирован, и позволяет:

  • Предоставлять тулы для LLM (function calling)
  • Дописывать системный промт
  • Участвовать в интерактивном старте — задавать вопросы, показывать меню
  • Реагировать на события через хуки
  • Читать свои настройки из config.toml
  • Писать в общий лог ядра

Философия. Ядро — гость в мире плагинов. Оно не знает, что делает плагин. Оно только спрашивает: «что ты умеешь?» и «сделай вот это». Всё остальное — дело плагина.

Быстрый старт

Чтобы написать плагин, нужно три вещи:

  1. Создать папку modules/my_plugin/src/
  2. Положить туда my_plugin.c с реализацией
  3. Добавить имя в config.toml → [plugins] load

Ядро само найдёт исходник, соберёт через CMake и загрузит. Отдельная сборка не требуется.

Версионирование ABI

ABI описывается двумя константами:

КонстантаЗначениеКогда меняется
SC_ABI_MAJOR 1 При ломающих изменениях — ядро отвергает несовместимые плагины
SC_ABI_MINOR 3 При добавлении полей в конец структур (обратно совместимо)

История версий

ВерсияЧто добавлено
1.0Базовый контракт: get_info, init, get_tools, call_tool, get_hooks
1.1Интерактив: prompt_yes_no, prompt_text, prompt_select, on_startup
1.2Системные промты: get_system_prompt
1.3Конфиг: config_get_string / int / bool / double, поле enabled

Обратная совместимость. Все новые поля добавляются только в конец структур. Старые плагины продолжают работать без пересборки. Поле struct_size позволяет ядру понять, какие поля есть у плагина.

Core API

Структура sc_core_api_t — то, что ядро даёт плагину. Указатель приходит в init() и валиден до вызова deinit().

typedef struct sc_core_api { ... } sc_core_api_t;

alloc / free

Выделение и освобождение памяти через аллокатор ядра.

void* (SC_CALL *alloc)(size_t size);
void (SC_CALL *free)(void* ptr);

Жёсткое правило. Всё, что плагин возвращает ядру — обязано быть выделено через core->alloc. Ядро освободит это само через core->free.

log

Запись в общий лог ядра. Идёт в data/logs/agent.log и (опционально) в stderr.

void (SC_CALL *log)(int level, const char* name, const char* msg);

Уровни — зеркало логгера ядра:

КонстантаЗначениеКогда использовать
SC_LOG_DEBUG0Отладка, детали
SC_LOG_INFO1Обычные события
SC_LOG_TOOL2Вызовы тулов
SC_LOG_WARN3Что-то подозрительное
SC_LOG_ERROR4Ошибки

prompt_yes_no / prompt_text / prompt_select

Интерактивные запросы к пользователю во время старта. Работают только из init() и on_startup().

int (SC_CALL *prompt_yes_no)(const char* question, int default_value);
int (SC_CALL *prompt_text)(const char* q, const char* dflt, char* out, size_t outsz);
int (SC_CALL *prompt_select)(const char* q, const char* const* opts, int n, int dflt);
ФункцияВозврат
prompt_yes_no1 — да, 0 — нет, -1 — прерывание
prompt_text0 — ок, строка в out, -1 — ошибка
prompt_selectИндекс выбранного пункта, -1 — ошибка

config_get_string / int / bool / double ABI 1.3

Чтение своей секции [plugins.<name>] из config.toml. Работает только во время init(). После возврата из init указатели становятся недействительными.

const char* (SC_CALL *config_get_string)(const char* key, const char* default_value);
int (SC_CALL *config_get_int)(const char* key, int default_value);
int (SC_CALL *config_get_bool)(const char* key, int default_value);
double (SC_CALL *config_get_double)(const char* key, double default_value);

Если ключ не найден в секции — возвращается default_value. Если секции нет вообще — работает так же, все ключи берутся из дефолтов.

Пример. Если в config.toml есть [plugins.telegram] typing_speed_min = 250, то внутри init() вызов g_core->config_get_int("typing_speed_min", 200) вернёт 250.

Внимание на строки. config_get_string возвращает указатель, живущий до конца init. Если нужно сохранить значение дольше — скопируйте его в свой буфер через strncpy или ручной цикл.

Plugin API

Структура sc_plugin_api_t — то, что плагин даёт ядру. Возвращается из единственной экспортируемой функции plugin_get_api().

SC_EXPORT const sc_plugin_api_t* SC_CALL plugin_get_api(void);

Эта функция — единственный символ, который ядро ищет в .dll.

get_info обязательно

Возвращает указатель на статическую структуру с метаданными плагина.

const sc_plugin_info_t* (SC_CALL *get_info)(void);

init / deinit init обязателен

Вызывается один раз при загрузке и выгрузке плагина. Внутри init доступны config_get_* и prompt_*.

sc_status_t (SC_CALL *init)(const sc_core_api_t* core, const char* config_json);
sc_status_t (SC_CALL *deinit)(void);

config_json — содержимое секции [plugins.<name>] в виде JSON. Обычно не нужен — используйте config_get_*.

get_tools опционально

Возвращает JSON-массив описаний тулов в формате OpenAI function calling.

sc_status_t (SC_CALL *get_tools)(char** out_json);

call_tool опционально

Обработка вызова тула от LLM.

sc_status_t (SC_CALL *call_tool)(const char* tool_name, const char* args_json, char** out_json);

get_hooks опционально

Возвращает массив зарегистрированных хуков.

sc_status_t (SC_CALL *get_hooks)(const sc_hook_reg_t** out_hooks, size_t* count);

on_startup ABI 1.1

Вызывается один раз после загрузки всех плагинов. Здесь плагин может задать вопросы через core->prompt_*.

sc_status_t (SC_CALL *on_startup)(void);

get_system_prompt ABI 1.2

Возвращает текст, который ядро добавляет к системному промту LLM.

sc_status_t (SC_CALL *get_system_prompt)(char** out_text);

Конфигурация

Каждый плагин настраивается через секцию [plugins.<name>] в config.toml. Ядро парсит все такие секции и передаёт каждому плагину его собственную — как JSON в init(), а также делает доступной через config_get_*.

Поле enabled

В любой секции можно поставить enabled = false — плагин будет пропущен при загрузке, но останется в [plugins] load. Удобно для быстрого включения/выключения без правки списка.

По умолчанию. Если секции нет или поля enabled нет — плагин считается включённым.

Пример

# Список плагинов для загрузки (порядок = порядок загрузки)
[plugins]
load = ["sysprompt", "remembrance", "telegram", "time"]

# --- Модуль telegram ---
[plugins.telegram]
enabled = true
session_name = "agent"
typing_speed_min = 200
typing_speed_max = 400

# --- Модуль time (не поддерживает настройки, но секция есть) ---
[plugins.time]
enabled = true

Внутри init() плагина telegram:

const char* s = g_core->config_get_string("session_name", "agent");
int v = g_core->config_get_int("typing_speed_min", 200);

s будет "agent", v будет 200 — значения взяты из конфига.

Хуки

Тулы

Тул — это функция, которую LLM может вызвать сама. Ядро получает описания от всех плагинов, склеивает их в один массив и передаёт модели.

Формат описания

JSON-массив в формате OpenAI function calling. Каждый тул — объект с полями name, description, parameters.

Обработка вызова

Когда модель решает вызвать тул, ядро находит плагин-владелец по имени и вызывает его call_tool().

Чтение конфига

Как читать свою секцию [plugins.<name>].

static sc_status_t init(const sc_core_api_t* core, const char* cfg) {
    g_core = core;
    (void)cfg;

    // Читаем настройки — с дефолтами на случай отсутствия ключа
    const char* name = core->config_get_string("name", "anonymous");
    int level = core->config_get_int("level", 5);
    int debug = core->config_get_bool("debug", 0);

    // ВАЖНО: скопировать строку, если нужно дольше init()
    snprintf(g_name, sizeof(g_name), "%s", name);

    return SC_OK;
}
